# 性能测试

本仓库的所有内容均为本地静态文本与规则，不涉及远程服务或数据库，因此性能测试聚焦于三类会随
输入规模增长的操作：PII 检测扫描、Schema/结构校验、内存占用。目标是尽早发现"长文本"或"大量规则"
是否会导致工具不可用（例如误用了平方级复杂度的算法），而不是承诺生产环境 SLA。

## 测试框架

- 测试脚本：临时的 Python 计时脚本（见下方"如何复现"），不作为仓库常驻文件，避免与
  `tools/validate.py` 的文件清单校验冲突；
- 计时方式：`time.perf_counter()`，内存用 `tracemalloc`；
- 环境：结果为**本地开发环境基线**，与 CI Runner 或用户机器的硬件规格不同，仅供判断复杂度趋势
  （是否线性增长），不作为生产环境性能承诺。测量环境：Python 3.12.3，Linux x86_64，4 vCPU。

## 场景 1：不同大小文本的 PII 检测性能（`tools/detect-pii.py`）

测试方法：对由固定基准字符串重复拼接而成的文本调用 `scan_text()`，覆盖每种识别符类型
（身份证号、手机号、案号等）。

| 文本大小 | 命中数 | 耗时 |
|---|---|---|
| 1,000 字符 | 32 | ~0.0002s |
| 10,000 字符 | 332 | ~0.0015s |
| 100,000 字符 | 3,332 | ~0.0150s |
| 1,000,000 字符 | 33,332 | ~0.1497s |

**结论**：耗时随文本大小近似线性增长（10 倍数据量约 10 倍耗时），适合处理单条脚本乃至整篇长文档
的输入材料。早期实现曾使用一个对已匹配区间做线性扫描的去重算法，在高命中密度文本上退化为平方级
复杂度（100,000 字符即需 0.6s+，1,000,000 字符测试超时未完成）；已改为"排序 + 单指针"合并算法
（见 `tools/detect-pii.py` 的 `scan_text`），修复后如上表所示为线性增长。

## 场景 2：Schema 验证性能

输入 Schema 为 `config/schema.json`（JSON Schema draft-07，14 个必填字段 + `key_facts` 嵌套对象）。
在无外部依赖的环境下，验证性能主要由 JSON 解析和字段遍历决定：

| 操作 | 次数 | 总耗时 |
|---|---|---|
| 单条素材 JSON 序列化 + 反序列化往返 | 1,000 次 | ~0.021s（约 0.021ms/次）|

**结论**：单条素材（约 1KB）的结构校验开销可忽略不计；`.github/workflows/content-validation.yml`
中对 PR 涉及的全部 JSON fixture 执行 Schema 校验时，预计在数百毫秒内完成，不构成 CI 瓶颈。

## 场景 3：内存使用

对 1,000,000 字符（约 1MB）的合成文本执行 `scan_text()` 并用 `tracemalloc` 采样：

| 输入大小 | 当前内存 | 峰值内存 |
|---|---|---|
| 1,000,000 字符（4 万命中） | ~13.6MB | ~22.8MB |

**结论**：内存占用与命中数量和候选匹配列表大小相关，1MB 文本、4 万命中时峰值仍在可接受范围内
（约为输入大小的 20 余倍，因每条命中额外保存类型、原文片段和位置字符串）。仓库中单个素材文件
通常远小于 1MB，实际占用会显著更低。

## v1.0 性能基线小结

| 指标 | 基线值（本地环境） |
|---|---|
| PII 扫描吞吐量 | 约 6.5M 字符/秒（线性） |
| 单条素材 Schema 校验开销 | 约 0.02ms/次 |
| 1MB 文本扫描峰值内存 | 约 22.8MB |

以上数值写入 `config/version.json` 的 `known_limitations` 时已注明"本地基线，非生产 SLA"，
避免误导为可承诺的性能保证。

## 如何复现

以下命令可在仓库根目录下临时运行以复现上述数据（不修改任何仓库文件）：

```sh
python3 - <<'PYEOF'
import time, importlib.util
spec = importlib.util.spec_from_file_location("detect_pii", "tools/detect-pii.py")
m = importlib.util.module_from_spec(spec)
spec.loader.exec_module(m)
base = "这是一段不含任何身份信息的示例文本，用于测试性能。身份证110101199003077758电话13812345678。"
for size in (1000, 10000, 100000, 1000000):
    text = (base * (size // len(base) + 1))[:size]
    start = time.perf_counter()
    hits = m.scan_text(text)
    print(size, time.perf_counter() - start, len(hits))
PYEOF
```
