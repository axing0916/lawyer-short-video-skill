# 5 分钟快速开始

目标：用一份已脱敏材料生成第一条“可进入人工终审”的草稿。若材料未脱敏，先停止，不计入 5 分钟。

## 第 1 分钟：准备环境

在 Codex 中打开本仓库所在文件夹。无需为本地 Skill 另行填写所谓“Codex API Key”；只有你自行编写外部 API 程序时才可能需要 API 凭据。

检查根目录存在 `SKILL.md`、`config/version.json` 和 `templates/input/content-brief.md`。

## 第 2 分钟：填写输入卡

复制 `templates/input/content-brief.md`，只填写已确认内容：

- 来源与使用授权
- 脱敏状态
- 法律领域和适用地区
- 关键事实、证据、程序阶段
- 传播主目标、时长、人设
- 不得披露内容

没有的信息写 `【待补充】`，不要猜。

## 第 3 分钟：运行请求

向 Codex 发出：

> 按本仓库 SKILL.md 处理这份输入卡。先做来源、脱敏和事实缺口检查；通过后生成一条 60 秒口播稿。传播目标为收藏，内容类型为干货实操。法律结论不确定处标【需核实】，不要补造案例或数据。

## 第 4 分钟：检查交付包

应至少得到：

1. 依据卡：来源、已知事实、待补充、待核验法律问题；
2. 口播稿与字幕稿；
3. 标题、画面建议和 CTA；
4. 发布状态。

如果只得到一段顺滑文案而没有依据卡，视为失败。

## 第 5 分钟：人工终审并保存

按 `checklists/pre-publish.md` 检查。需要 Obsidian 时，将结果保存到 vault 内的普通 Markdown 文件；首次使用无需安装插件。

## 成功标准

- 没有出现输入中不存在的人名、金额、日期、证据或结果；
- 未脱敏或关键事实不足时，系统确实停止；
- 法律疑点明确标为 `【需核实】`；
- 文案可朗读，但未承诺胜诉、追回或流量。

## 60 秒排障

- 找不到 Skill：确认从仓库根目录打开项目，且文件名是 `SKILL.md`。
- 输出编造细节：停止使用该稿，要求重做事实清单并逐项标来源。
- 时长超出：选择 `prompts/duration/60s.md` 后重新压缩并朗读计时。
- Obsidian 看不到文件：确认保存路径确实位于 vault，而不是仓库目录。
