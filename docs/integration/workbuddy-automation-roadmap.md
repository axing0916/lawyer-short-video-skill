# WorkBuddy 自动化路线图

本文档说明仓库描述中提到的 "WorkBuddy 自动化" 当前的真实支持范围、理论上可行的集成路径，以及后续版本的规划。它不代表已交付功能；实现前的所有条目仍需按 `modules/05-integration/workbuddy.md` 的要求补充官方接口文档、认证方式等信息。

## 当前版本（v1.0）支持范围

- **状态**：`not_implemented`（与 `config/integration-settings.json` 中 `workbuddy.status` 一致）。
- 仓库不包含任何 WorkBuddy API 客户端、Webhook 接收端或自动化脚本。
- 仓库产出的内容为 Markdown 文件（依据卡、口播稿、字幕、标题备选等），可以手动复制到 WorkBuddy 或其他工作台，但复制不等于"同步"，也不会自动保留版本追踪、状态流转等信息。
- 若声称"已与 WorkBuddy 自动化集成"，属于与现状不符的表述，不得出现在对外文案中。

## 理论集成路径（尚未实现，仅供规划参考）

以下场景描述的是可能的技术方向，实现前均需完成对应的官方接口调研、权限评估和测试，任何一项缺失都应继续保持 `not_implemented` 状态。

### 场景 1：数据统计回写

- 目标：将发布后的观看、收藏、转发等指标从 WorkBuddy（或发布平台）回写到 `modules/04-data` 的记录文件。
- 需要：只读的统计数据接口、字段映射表、去重与口径统一规则、写入前的人工确认步骤。
- 风险：若接口权限过宽或缺少校验，可能引入未经核实的数据，违反"因果论断保护"要求（见 `modules/04-data/README.md`，如已实现）。

### 场景 2：法律规则更新提醒

- 目标：当 `docs/legal-verification.md` 引用的法规、司法解释发生变化时，通过 WorkBuddy 通知相关内容需要复核。
- 需要：权威法规更新源的订阅方式、变更与已发布内容的关联规则、提醒触达机制（不能替代人工核验本身）。
- 风险：自动提醒不能替代人工核验，仅作为"需复核"的线索来源。

### 场景 3：自动 PR 生成

- 目标：内容通过质量网关后，自动在仓库创建 Pull Request，附带依据卡和核验清单，供人工终审。
- 需要：仓库写权限的最小化授权、分支保护规则确认、PR 模板、失败回滚方式。
- 风险：任何自动化都不得跳过 `QUALITY-GATES.md` 中定义的人工终审环节。

## v1.0 推荐的手动流程

在自动化实现之前，推荐按以下流程手动衔接 WorkBuddy 或其他工作台：

```
输入材料（脱敏）
      │
      ▼
本仓库工作流生成 Markdown 产出
（依据卡 / 口播稿 / 字幕 / 标题备选 / CTA）
      │
      ▼
人工核对 QUALITY-GATES.md 各项门槛
      │
      ▼
人工复制 Markdown 内容到 WorkBuddy
（或其他工作台）
      │
      ▼
人工在 WorkBuddy 中完成排期、发布
      │
      ▼
发布后指标由人工记录回
modules/04-data（如适用）
```

## 后续版本规划（暂定，不构成承诺）

| 版本 | 计划范围 | 前置条件 |
|------|----------|----------|
| v1.1 | 提供数据回写字段映射模板（仍为人工填写，不含自动接口调用） | 无 |
| v1.2 | 探索只读统计数据接口对接（场景 1），产出接口调研报告 | 获取官方接口文档与测试环境 |
| v1.5 | 法律规则更新提醒的技术选型与原型（场景 2） | 确认权威数据源及更新频率 |
| v2.0 | 评估自动 PR 生成（场景 3）及配套权限、审计机制 | 完成 v1.x 阶段的安全评审 |

以上版本节奏仅为规划参考，具体是否实现、何时实现取决于官方接口可用性、维护资源和安全评审结果。

## 如何贡献

如果你有明确的 WorkBuddy 集成需求或已实现的原型代码，欢迎通过 Pull Request 提交，并在描述中说明：

- 使用的官方接口/文档链接；
- 认证方式与所需权限范围（遵循最小权限原则）；
- 数据流向图和冲突处理策略；
- 对应的自动化测试；
- 撤销/回滚方法。

未附带以上信息的集成代码不会被合并。
