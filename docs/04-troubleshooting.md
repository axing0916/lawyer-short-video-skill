# 故障排查

以下问题按“现象—原因—处理”排列。

1. **Codex 没识别 Skill**：项目未从仓库根目录打开，或缺少 `SKILL.md`。确认路径和文件名。
2. **系统索要 API Key**：本地使用 Skill 不以 API Key 为必需条件。只有自建外部 API 调用才需要，并不得写入仓库。
3. **输出补造案情**：输入存在空白但提示词要求完整故事。停止发布，重建事实/主张/缺口清单。
4. **把当事人陈述写成事实**：来源类型未标注。将其改为“据材料中的单方陈述”，并标待证状态。
5. **引用了不存在的法条**：模型依据记忆生成。删除引用并用权威现行来源人工核验。
6. **法律规则可能已失效**：缺少效力和时间检查。标 `【需核实】` 后再发布。
7. **主体前后变化**：角色映射不统一。建立甲方、乙方、公司和律师的固定称谓表。
8. **金额对不上**：多个来源或单位混用。回到内部材料逐项核算，发布稿使用核验后的口径。
9. **日期与期间矛盾**：精确日期被泛化后影响计算。内部保留原日期，外部只展示不影响结论的区间。
10. **脱敏后仍可识别**：组合信息过于独特。进一步泛化地区、行业、金额和时间，或放弃案例叙事。
11. **不确定是否获得授权**：授权记录缺失。标 `【待补充】`，不得按真实经历发布。
12. **脚本超过时长**：结构过多或口播速度假设不实。实际朗读计时，优先删重复信息。
13. **脚本像文章而非口播**：长句、名词堆叠。拆成一口气能说完的句子，并保留逻辑连接。
14. **Hook 很刺激但正文接不住**：开头承诺与正文价值不一致。降低 Hook 承诺或补足答案。
15. **“反常识”变成错误结论**：为了冲突删除条件。恢复适用边界，必要时改为“很多人忽略的条件”。
16. **CTA 过度营销**：暗示结果保证或制造稀缺。改为保存材料、核对证据或在需要时寻求个案咨询。
17. **Obsidian 看不到模板**：文件不在 vault 或扩展名错误。确认 vault 路径和 `.md` 后缀。
18. **Obsidian 没自动同步**：本项目默认没有云同步功能。使用 Obsidian 自身同步方案或 Git，并单独配置与测试。
19. **数据字段是空的**：尚未发布或未录入。保留 `null`，不要用行业平均数填充。
20. **咨询率异常高**：分母或咨询定义错误。区分播放、主页访问、私信、有效咨询、预约和委托。
21. **批量五条内容高度重复**：只换了开头。回到角度矩阵，为每条指定不同受众问题。
22. **案例库看起来不像真实案例**：本库只提供虚构教学情景。真实内容必须由用户提供已脱敏来源。
23. **GitHub 校验失败**：JSON、链接或必需文件不一致。运行 `tools/validate.py` 并按具体路径修复。
24. **版本日期冲突**：多处手工填写。以 `config/version.json` 为真源后同步展示文件。
25. **强制写满导致重复**：把字数当验收标准。以覆盖、可追溯和测试通过为准，删除无价值重复。
