# 使用手册

## 1. 系统总览

系统由输入、拆解、生成、审核和数据五个阶段组成。人工律师始终负责材料可用性、法律核验和最终发布决定。

## 2. 输入

先使用 `templates/input/content-brief.md`。案例材料还要填写：案件阶段、事实来源、证据状态、公开授权和不可披露信息。文章或法规材料要记录标题、作者/发布机关、链接、发布日期、效力状态和访问日期。

任何客户材料都应由用户先自行脱敏；不要上传未脱敏原始案卷。

## 3. 拆解

拆解不是“把一篇内容变成五条文案”，而是先区分：

- 已确认事实
- 当事人陈述或单方主张
- 可由证据支持的判断
- 法律问题和适用条件
- 信息缺口
- 可以公开的受众问题

再从五种传播目标中选择角度。若五个角度只是换标题、事实和价值相同，不应强行批量生成。

## 4. 生成

一次只选择：一个主传播目标、一个内容类型、一个法律领域、一个时长和一个人设。副目标最多一个。

主提示词位于 `modules/03-generation/prompts/00-main-prompt.md`。生成顺序为依据卡、结构草图、口播稿、辅助资产、终检结果。

## 5. 五种传播目标

| 目标 | 核心价值 | 可观察指标 | 主要风险 |
|---|---|---|---|
| 收藏 | 提供可复用步骤 | 收藏率、收藏数 | 清单看似通用但忽略例外 |
| 讨论 | 纠正常见误区 | 有效评论率 | 为冲突而歪曲法律 |
| 转发 | 帮观众替某类人表达 | 分享率 | 煽情或标签化群体 |
| 探索 | 用信息差维持注意 | 前段留存、平均观看 | 虚假内幕、故意隐瞒限制 |
| 专业信任 | 展示判断过程与边界 | 关注、主页访问、有效咨询 | 伪造履历或暗示结果保证 |

点赞、流量、涨粉是指标或结果，不是可保证的“公式”。

## 6. 四种内容类型

- 故事驱动：通过决策和后果组织信息，案例必须真实授权或标为虚构教学情景。
- 教育知识：解释规则、误区和边界，必须核验法律效力。
- 对比冲击：比较不同选择的条件与代价，不做绝对化反转。
- 干货实操：提供步骤、材料清单和停止条件，不把一般建议当个案方案。

## 7. 审核

先做事实与法律审核，再做隐私与执业风险审核，最后做口播质量审核。不能用“更顺口”掩盖事实缺口。

## 8. Obsidian

Obsidian 把 vault 中的 Markdown 显示为笔记。本项目提供模板和目录建议，不宣称无需授权即可自动写入。详见 `docs/integration/obsidian-guide.md`。

## 9. 数据复盘

发布后记录真实数据。不同平台、账号阶段、投放与自然流量要分开。咨询数还应区分无效咨询、有效咨询、预约和正式委托。详见 `docs/metrics.md`。

## 10. 交付格式

每条内容固定交付：依据卡、口播稿、字幕、标题备选、画面建议、CTA、风险与待核验项、发布状态。任何预测必须写成假设，不得伪装成历史结果。
